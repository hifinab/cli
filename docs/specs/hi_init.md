# `hi init` specification

Status: Draft

Dependencies: `uv` on `PATH`; existing release installation.

## Goal

Create predictable agent-driven repositories without requiring users to remember
the bootstrap commands or directory conventions. A bare `hi init` is an
interactive helper; `hi init <template>` selects a template directly.

## Command surface

```text
hi init
hi init py [directory]
hi init quant [directory]
hi init webapp [directory]
```

When no directory is supplied, the target is the current working directory.
Template names are reserved command arguments rather than project names.

The `py` template is defined here. The `quant` and `webapp` variants extend this
planner and safety contract and are specified separately in
`hi_init_quant.md` and `hi_init_webapp.md`.

## Interactive helper

`hi init` asks for:

1. Template: `py`, `quant`, or `webapp`
2. Project name
3. Target directory, defaulting to the current directory

Before changing the filesystem, it prints the selected template, target,
external commands, and generated paths. The user must confirm the plan. EOF or
a negative response exits without changes.

The wizard and direct command forms use the same planner and generator; the
wizard must not have separate template behavior.

## Python template

`hi init py [directory]` creates the baseline Python repository.

### Preconditions

- `uv` is available on `PATH`.
- The target either does not exist or is a directory.
- The target contains no file that the plan would overwrite.
- The project name is valid for `uv init`.

All conflicts are reported before running `uv` or writing files. There is no
implicit force mode.

### External commands

Run these commands, in order, with the target directory as the working
directory:

```sh
uv init
uv venv
```

Attach stdin, stdout, and stderr so `uv` errors remain visible. A non-zero exit
stops initialization and is returned as a `hi` error. `hi` must not claim that
the repository is complete after either command fails.

### Generated structure

The resulting repository contains the files generated by `uv` plus this Hifin
structure:

```text
.
├── .hifin/
│   └── template.json
├── AGENTS.md
├── agents/
│   └── README.md
├── skills/
│   └── README.md
├── source/
│   └── README.md
├── tests/
│   └── README.md
├── data/
│   └── README.md
├── docs/
│   ├── specs/
│   │   └── README.md
│   └── roadmap.md
├── .gitignore
└── README.md
```

Purpose documentation is used instead of empty directories so Git retains the
shape. The `data/README.md` explains the local data policy; `.gitignore` excludes
datasets and generated results while retaining the documentation file.

### Template metadata

`.hifin/template.json` records the generator identity:

```json
{
  "template": "py",
  "version": 1,
  "generatedBy": "hi <version>"
}
```

The file is machine-readable state for future template checks and upgrades. It
must not contain absolute paths, usernames, credentials, or machine-specific
configuration.

### Repository instructions

`AGENTS.md` defines the repository-wide development contract, including:

- Keep production Python under `source/`.
- Keep behavioral verification under `tests/`.
- Keep durable decisions and usage documentation under `docs/`.
- Write feature specifications under `docs/specs/`.
- Do not commit datasets, credentials, virtual environments, caches, or results.
- Use `uv` for dependency and virtual-environment operations.

`agents/README.md` documents where project-specific agent role templates belong.
`skills/README.md` documents where reusable project skill templates belong.
Neither directory should contain fake executable agents or placeholder skills
that claim capabilities they do not implement.

### Roadmap template

`docs/roadmap.md` starts with sections for planned work, decisions required, and
completed milestones. It describes the generated project, not the `hi` CLI
roadmap.

## Safety and reruns

- Resolve and normalize the target before presenting the plan.
- Never delete existing content.
- Never overwrite a non-empty file.
- If every planned file already matches and the `uv` project and `.venv` exist,
  report that the template is already initialized and exit successfully.
- If existing output differs, report every conflicting path and exit before
  mutation.
- Temporary files must be created inside the target and renamed atomically.
- Print each executed command and created file without printing environment
  variables or credentials.

## Output

Successful initialization ends with:

- Template and target directory
- Commands executed
- Files and directories created
- Virtual environment path
- The next commands required to enter the environment and begin work

No analytics or repository contents are uploaded.

## Acceptance criteria

1. `hi init` presents the template, project-name, and target-directory prompts.
2. Cancelling the wizard leaves the filesystem unchanged.
3. `hi init py` runs `uv init` followed by `uv venv` in the selected target.
4. The Python template creates `source/`, `tests/`, `data/`, `docs/`,
   `docs/specs/`, and `docs/roadmap.md` with tracked purpose documentation.
5. The template creates repository, agent, and skill instructions without
   generating fake implementations.
6. Existing conflicting files are listed before any command or write occurs.
7. A matching initialized template is a successful no-op.
8. Failures from `uv` are surfaced and stop later generation.
9. Generated metadata contains the template and generator versions but no
   machine-specific or secret data.
